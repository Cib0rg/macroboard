MacroKeyboard · Developer Guide

Plugin Development

Extend the MacroKeyboard with plugins that run on any button press. Plugins can toggle smart home entities, run scripts, talk to external APIs, or do anything a process can do.

Getting Started

Overview

MacroKeyboard supports two plugin execution models. Choose based on your language preference and how much you need from the device.

executable

External process

  • Any language: C#, Node.js, Python, Go…
  • Communicates via WebSocket (port 28196)
  • Stream Deck SDK-compatible protocol
  • Subprocess managed by backend
  • Crashes auto-detected and logged
  • Can bundle a Property Inspector UI (HTML)
managed

In-process .NET DLL

  • .NET 8+ class library, implements IPlugin
  • Direct device API — no WebSocket needed
  • Loaded into isolated AssemblyLoadContext
  • Hot-unload on stop, no process kill
  • Simpler for small .NET integrations
  • No Property Inspector support yet
Stream Deck compatibility. The executable protocol is intentionally compatible with Elgato's Stream Deck plugin SDK. Existing SD plugins can run on MacroKeyboard with minimal changes — primarily replacing setImage with mkSetButtonDisplay for native rendering.

Getting Started

Plugin structure

A plugin is a folder whose name ends in .sdPlugin, placed in the backend's plugins/ directory. The backend also accepts .zip archives under that name and extracts them automatically.

com.vendor.myplugin.sdPlugin/ ├── manifest.json ← required ├── MyPlugin.exe ← entry point (or .js, .py, .dll) ├── pi.html ← Property Inspector UI (optional) └── images/ ├── icon.png └── action-icon.png

On startup the backend scans the plugins/ directory, parses every manifest.json, and launches each plugin process. The plugin ID is taken from manifest.json → Id, or derived from the folder name by stripping .sdPlugin.

Repackaging. If a .zip archive is newer than its extracted directory, the backend re-extracts it automatically on next start. Ship updates as a new zip.

Getting Started

manifest.json

The manifest declares the plugin's identity, entry point, and the actions it exposes. Every field is parsed with Stream Deck SDK tolerance (e.g. Category can be a string or an array).

manifest.json 
{
  "Id":          "com.vendor.myplugin",   // globally unique, reverse-domain
  "Name":        "My Plugin",
  "Version":     "1.0.0",
  "Author":      "Vendor",
  "Description": "Does something useful",

  "Type":        "executable",         // or "managed"
  "EntryPoint":  "MyPlugin.exe",       // relative path; .js/.py/.dll also valid
  "Runtime":     "node",               // omit for .exe/.dll; "python3" for Python

  "PropertyInspectorPath": "pi.html",  // default PI for all actions

  "Actions": [
    {
      "Id":       "toggle",            // short ID used in keyDown events
      "Name":     "Toggle Entity",
      "Tooltip":  "Toggle a Home Assistant entity",
      "Icon":     "images/action-icon.png",
      "PropertyInspector": "pi-toggle.html",  // per-action override
      "States": [
        { "State": 0, "Name": "Off" },
        { "State": 1, "Name": "On"  }
      ]
    }
  ]
}

Windows/macOS entry points

For cross-platform plugins, use platform-specific fields. The backend resolves in this order: CodePathWin / CodePathMac → CodePath → EntryPoint.

"CodePath":    "dist/plugin.js",
"CodePathWin": "dist/plugin-win.exe",
"CodePathMac": "dist/plugin-mac"

Plugin Types

Executable plugin

The backend launches your executable as a subprocess and expects it to connect to the local WebSocket server and register itself.

Launch arguments

Your process is started with these fixed CLI arguments:

MyPlugin.exe \
  -port 28196 \
  -pluginUUID com.vendor.myplugin \
  -registerEvent registerPlugin \
  -info '{ "application": {...}, "devices": [...] }'
1

Connect to WebSocket

Open a WebSocket to ws://localhost:{port}. The port comes from the -port argument.

2

Register the plugin

Send the registration message immediately. The backend queues any willAppear events until registration completes.

{ "event": "registerPlugin", "uuid": "com.vendor.myplugin" }
3

Restore global settings

Request your persisted global settings (API tokens, URLs, etc.):

{ "event": "getGlobalSettings", "context": "com.vendor.myplugin" }

The backend replies with didReceiveGlobalSettings.

4

Handle button events

Receive and process willAppear, keyDown, keyUp events. Update button display as needed.

Using the SdConnection helper (C#)

The Home Assistant plugin in MacroKeyboard.Plugin.HomeAssistant includes a ready-made SdConnection WebSocket client. Copy it into your project as a starting point.

Program.cs 
var args = SdArgs.Parse(argv);
var conn = new SdConnection(args.Port, args.PluginUUID);

conn.WillAppear  += OnWillAppear;
conn.KeyDown     += OnKeyDown;
conn.DidReceiveGlobalSettings += OnGlobalSettings;

await conn.ConnectAsync(ct);
await conn.RunAsync(ct);  // blocks until WS closes
Handling keyDown 
async void OnKeyDown(JsonElement msg)
{
    var context  = msg.GetProperty("context").GetString();
    var actionId = msg.GetProperty("action").GetString();
    var settings = msg.GetProperty("payload").GetProperty("settings");

    await DoSomethingAsync(actionId, settings);

    await conn.SetButtonDisplayAsync(context, "Done!", isOn: true, ct);
}

Node.js skeleton

const WebSocket = require('ws');

const args  = parseArgs(process.argv);
const ws    = new WebSocket(`ws://localhost:${args.port}`);

ws.on('open', () => {
  ws.send(JSON.stringify({ event: 'registerPlugin', uuid: args.pluginUUID }));
});

ws.on('message', (data) => {
  const msg = JSON.parse(data);
  if (msg.event === 'keyDown') handlePress(msg);
});

function send(obj) { ws.send(JSON.stringify(obj)); }

Plugin Types

Managed plugin (.NET DLL)

A managed plugin is a .NET class library that implements IPlugin. No WebSocket, no subprocess — the backend calls your methods directly.

1. Project setup

Create a .NET 8+ class library targeting net8.0. Add a reference to MacroKeyboard.Core (contains IPlugin and IPluginContext).

manifest.json 
{
  "Id":         "com.vendor.myplugin",
  "Name":       "My Plugin",
  "Type":       "managed",
  "EntryPoint": "MyPlugin.dll",
  "Actions": [
    { "Id": "run", "Name": "Run Action" }
  ]
}

2. Implement IPlugin

MyPlugin.cs 
public class MyPlugin : IPlugin
{
    private IPluginContext? _ctx;

    public async Task InitializeAsync(IPluginContext context, CancellationToken ct)
    {
        _ctx = context;
        // Load persisted settings
        var settings = await context.GetSettingsAsync<MySettings>(ct);
    }

    public async Task OnButtonPressedAsync(
        string actionId, string? settings, int buttonIndex, CancellationToken ct)
    {
        await DoWorkAsync();
        await _ctx!.SetButtonTitleAsync(buttonIndex, "Done", ct);
        await _ctx.SetLedColorAsync(buttonIndex, r: 0, g: 220, b: 0, ct);
    }

    public async Task OnButtonReleasedAsync(
        string actionId, string? settings, int buttonIndex, CancellationToken ct) { }

    public Task StartAsync(CancellationToken ct) => Task.CompletedTask;
    public Task StopAsync(CancellationToken ct)  => Task.CompletedTask;
    public void Dispose() { }
}

IPluginContext API

MethodDescription
SetButtonTitleAsync(index, text)Render text label on a button display
SetButtonImageAsync(index, bytes)Upload raw image bytes to a button display
SetLedColorAsync(index, r, g, b)Set the button's LED ring color
ShowAlertAsync(index)Flash red LED to indicate failure
GetSettingsAsync<T>()Load plugin settings from disk as T
SaveSettingsAsync<T>(value)Persist plugin settings to disk as JSON
LogInfo / LogWarning / LogErrorLog to backend's Serilog logger

Protocol

Button lifecycle

The backend notifies plugins as buttons come in and out of view (due to folder navigation or profile changes) and when they are pressed.

Sequence · Device connected or folder entered
backend
→
willAppear
Sent for every visible plugin button. Contains context, action ID, and current settings.
plugin
→
mkSetButtonDisplay
Plugin initialises the button display. Render based on the current external state.
backend
→
keyDown
User presses the button. payload.settings contains the live sidecar settings.
plugin
→
mkSetButtonDisplay
Update button to reflect the new state.
backend
→
keyUp
Button released.
backend
→
willDisappear
User navigates to a folder or profile changes. Stop polling this button's state.

willAppear payload

{
  "event":   "willAppear",
  "action":  "toggle",
  "context": "com.vendor.myplugin:3",
  "device":  "MK_DEVICE_0",
  "payload": {
    "settings":    { "entityId": "light.bedroom" },
    "coordinates": { "column": 3, "row": 0 },
    "state":        0,
    "isInMultiAction": false
  }
}
Settings on willAppear are a snapshot. They reflect the value at the time the profile was saved, not the live sidecar value. The button press (keyDown) delivers live sidecar settings. If your plugin writes settings frequently via setSettings, don't rely on willAppear for the latest values.

Protocol

Events → backend

Messages your plugin sends over WebSocket to the backend.

EventDescription
registerPlugin First message after WS connect. Must include "uuid": "<pluginId>"
mkSetButtonDisplay Native firmware rendering. Payload: { text, isOn }. Green ring when on, purple when off. Preferred.
mkSetButtonError Red error ring. Payload: { message }. No image transfer.
setTitle Render text on the button display. Payload: { title }
setImage Upload image to button. Payload: { image: "data:image/png;base64,…" }. Converted to JPEG and stored on device.
setState Set multi-state button index. Payload: { state: 1 }
showAlert Flash red LED. No payload required.
showOk Flash green LED. No payload required.
setSettings Save per-button settings (sidecar). Payload: any JSON object.
getSettings Request current per-button settings. Backend replies with didReceiveSettings.
setGlobalSettings Save plugin-wide settings (API key, URL, etc.).
getGlobalSettings Request plugin-wide settings. Backend replies with didReceiveGlobalSettings.
sendToPropertyInspector Send custom data to the currently open Property Inspector for a context.
openUrl Open a URL in the default browser. Payload: { url }
logMessage Append a line to the backend log. Payload: { message }

Message envelope

All messages from plugin → backend use this shape:

{
  "event":   "mkSetButtonDisplay",
  "context": "com.vendor.myplugin:3",  // button context
  "payload": {
    "text":  "Bedroom\nON",
    "isOn":  true
  }
}

Protocol

Events ← backend

Messages the backend sends to your plugin.

EventDescription
willAppear A plugin button became visible. Contains context, action, and snapshot settings.
willDisappear A plugin button is leaving view (folder nav, profile change). Stop updates for this context.
keyDown Button pressed. Contains live sidecar settings in payload.settings.
keyUp Button released.
didReceiveSettings Response to getSettings, or pushed when PI calls setSettings.
didReceiveGlobalSettings Response to getGlobalSettings, or pushed when any PI updates global settings.
propertyInspectorDidAppear User opened the configuration UI for a button. Push fresh state to PI.
propertyInspectorDidDisappear Configuration UI closed.
sendToPlugin Custom message from the Property Inspector. Route based on payload.action.
applicationDidLaunch Backend started. Re-initialize any connections.
deviceDidConnect Physical device attached.
deviceDidDisconnect Physical device detached.

Protocol

Button context

Every button is identified by a context string that encodes the plugin ID, optional folder, and button index. It is stable across sessions for a given button slot and is safe to use as a map key.

Root button 3 com.vendor.myplugin:3 Folder 2, button 5 com.vendor.myplugin:F2:5

Use the context as the value for "context" in every message you send. It comes to you in willAppear and all subsequent events for that button.

Sidecar file path. Settings are stored at %AppData%\MacroKeyboard\plugins\{pluginId}\actions\{context_safe}.json where colons and slashes in the context are replaced with underscores. E.g. com_vendor_myplugin_3.json.

Features

Settings

Two settings scopes. Action settings are per-button; global settings are shared across all instances of the plugin.

Action settings (per button)

Action settings hold configuration specific to one button instance — e.g. which entity to toggle, or which shortcut to run. They survive profile reloads via a sidecar JSON file.

Write and read action settings
plugin / PI
→
setSettings
Payload is any JSON object. Written immediately to the sidecar file.
backend
→
didReceiveSettings
Broadcast to all open Property Inspectors for that context after every write.
plugin
→
getSettings
Request the current sidecar settings at any time.

Global settings (plugin-wide)

Global settings hold data that applies to the entire plugin — credentials, server URL, etc. Call getGlobalSettings on startup to restore them.

// On startup — restore credentials
send({ event: 'getGlobalSettings', context: pluginId });

// In didReceiveGlobalSettings handler
const { haUrl, haToken } = msg.payload.settings;
connectToHomeAssistant(haUrl, haToken);

// Save from Property Inspector
send({ event: 'setGlobalSettings', context: pluginId,
        payload: { haUrl, haToken } });

Storage path: %AppData%\MacroKeyboard\plugins\{pluginId}\global.json

Features

Display commands

Each button has a 160×160 circular display and an LED ring. You have three ways to update the display.

Native · Preferred
mkSetButtonDisplay

Firmware renders text with a color ring. Green ring = on, purple ring = off. No image file, no SPIFFS write, instant.

Native · Error
mkSetButtonError

Red ring with a short error label. Use when the plugin is disconnected or the action failed.

Image upload
setImage

Upload a base64 PNG/JPG. Backend converts to JPEG and stores on device. Use for branded or rich-media buttons.

mkSetButtonDisplay 
{
  "event":   "mkSetButtonDisplay",
  "context": "com.vendor.myplugin:3",
  "payload": {
    "text":  "Bedroom\nON",   // \n splits into two lines, max 52 bytes UTF-8
    "isOn":  true             // true = green ring, false = purple ring
  }
}
setImage (base64 PNG) 
{
  "event":   "setImage",
  "context": "com.vendor.myplugin:3",
  "payload": {
    "image": "data:image/png;base64,iVBORw0KGg..."
  }
}
LED ring vs. display. showAlert / showOk flash the LED ring independently of the display content. For managed plugins, IPluginContext.SetLedColorAsync() sets an arbitrary RGB color on the ring.

Features

Property Inspector

The Property Inspector is an HTML page that lets users configure a button's action. It runs in a WebView and communicates with your plugin via the same WebSocket.

The backend serves PI assets from http://localhost:8787/plugins/{pluginId}/{piPath}. Point a WebView at this URL; the backend injects the connection bootstrap script automatically.

Property Inspector lifecycle
backend
→
didReceiveSettings
Current action settings pushed to PI immediately on open.
backend
→
didReceiveGlobalSettings
Current global settings pushed to PI on open.
backend
→
propertyInspectorDidAppear
Sent to plugin — plugin can now push UI state (entity list, connection status).
PI
→
sendToPlugin
Custom message: { action: "testConnection", haUrl, haToken }
plugin
→
sendToPropertyInspector
Custom message back: { action: "connectionStatus", status: "ok" }
PI
→
setSettings
PI saves the user's configuration. Backend persists to sidecar file.

PI bootstrap (auto-injected)

When the backend serves your pi.html, it injects a script that calls connectElgatoStreamDeckSocket(port, uuid, registerEvent, info, actionInfo) just before </body>. You only need to implement that function:

pi.html 
function connectElgatoStreamDeckSocket(port, uuid, registerEvent, info, actionInfo) {
    const ws = new WebSocket(`ws://localhost:${port}`);

    ws.onopen = () => {
        // registerEvent is "registerPropertyInspector" when opened as PI
        ws.send(JSON.stringify({ event: registerEvent, uuid }));
    };

    ws.onmessage = (e) => {
        const msg = JSON.parse(e.data);
        if (msg.event === 'didReceiveSettings') populateForm(msg.payload.settings);
        if (msg.event === 'sendToPropertyInspector') handlePluginMsg(msg.payload);
    };

    // Save settings when form changes
    document.getElementById('entityId').onchange = (e) => {
        ws.send(JSON.stringify({
            event: 'setSettings', context: uuid,
            payload: { entityId: e.target.value }
        }));
    };
}
